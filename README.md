## What This Does

<!-- The path a submission takes, from arriving to the label a reader sees.
     Six or seven steps — this is the trace you wrote in Milestone 1. -->

This is the path a submission takes:
1. **Submit the text:** The user sends a text and a `creator_id` to the `/submit` endpoint through a POST request.
2. **Validate the input:** The system checks that the request contains the required information before processing the text.
3. **Analyze the text with the model:** The `detector.py` module analyzes how predictable the text is and produces a `model_score`.
4. **Analyze the writing style:** The `stylometry.py` module examines writing patterns, such as sentence structure and word usage, and produces a `style_score`.
5. **Combine the results:** The `scoring.py` module combines both signals to calculate a final confidence score.
6. **Assign a label:** Based on the combined score and the defined thresholds, the system assigns one of three labels: high-confidence human, unsure, or high-confidence AI.
7. **Record and return the result:** The system assigns a unique `content_id`, saves the decision in the audit log, and returns a JSON response containing the classification, confidence score, label, and both signal scores.

### API Contracts
1. POST /submit
This endpoint receives a text and analyzes whether it might be AI-generated.
Input: text (the writing to analyze) and creator_id (who submitted it).
Output: content_id (unique text ID), guess (estimated classification), confidence (combined score), label (message for the user), model_score (model result), and style_score (writing style result).

2. POST /appeal
This endpoint allows a person to request a review of a result.
Input: content_id (which text is being appealed) and reasoning (why the person disagrees).
Output: content_id, status (under_review), and message (confirmation that the appeal was recorded).
The system should check that the content exists before accepting an appeal. An appeal does not automatically change the original result.

### False Positive Scenario
A student writes an essay in English using simple vocabulary and repetitive expressions because English is not her first language. The system incorrectly identifies her writing as potentially AI-generated.
For this example, the system assigns a hypothetical score of 0.92, indicating a high likelihood of AI-generated writing according to its scoring method.
Instead of accusing the student, the system displays this message:
"This text shows patterns potentially associated with AI-generated content. This result is not definitive."
The student can submit an appeal explaining that she wrote the essay herself and providing additional information, such as earlier drafts.
The system records the appeal using the document's unique `content_id` and changes its status to `under_review`. The original classification is not automatically changed.
This example shows why the system needs carefully chosen thresholds and an appeal process. A false positive can unfairly affect a person who wrote their own work.

## Signals and Scoring

<!-- For each signal: what property it measures, why that might differ between
     human and AI writing, and WHAT IT CAN'T SEE.

### Signal one — the model signal

**What it measures:**
The model analyzes how predictable the text is based on language patterns. It produces a score that helps estimate whether the text might have been generated by AI.
**Why that might differ between human and AI writing:**
AI-generated text may follow more predictable language patterns, while human writing can include more variation in word choices and expressions.
**What it can't see:**
The model cannot determine with certainty who wrote the text. For example, a person whose first language is not English might use simple vocabulary, repetitive words, or formal expressions. The model could incorrectly identify this writing as AI-generated.
Also, AI-generated text that has been significantly edited by a person might be more difficult for the model to identify.

### Signal two — the style signal

**What it measures:**
This signal analyzes writing characteristics, such as sentence length, vocabulary variety, and repetitive patterns.
**Why that might differ between human and AI writing:**
Human and AI-generated texts may have different writing patterns. For example, AI-generated text might use more consistent sentence structures or repetitive expressions.
**What it can't see:**
Writing style alone cannot prove whether a text was written by AI or a person. Someone might naturally write in a formal or repetitive way, especially when English is not their first language.
Also, a person could modify AI-generated text by changing words or sentence structures, making it more difficult for this signal to recognize the original patterns.
